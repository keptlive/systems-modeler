# May presets and preserved old links

Local implementation reviewed for a future release; not a deployment announcement. The source catalog has one May logistic generation map, ID may-chaos-population-eco. The older May's Logistic Map Model and May Ecological Chaos Model are parameter presets of the same mechanism.

After release, opening an old editor link with model=may-logistic-chaos loads r=3.7; model=may-ecological-chaos-eco loads r=3.8. Each fallback is a fresh unsaved draft with Population=0.1, generations0..100, Euler and dt=discrete_period=1. Existing server definitions and existing local saved copies with those requested IDs take priority. Nothing is saved during loading. A visible notice explains the migration; choosing Save creates a separate model and does not replace the canonical model. No duplicate catalog entry is created by an alias. A locally saved old-ID copy still loads unchanged; on an explicit Save, an existing server copy updates normally. If that old server ID is gone (PUT404), Save creates a separate copy instead. Other server errors do not trigger duplicate creation.

The ordinary retained canonical defaults to r=3.9. Inspect already exposes its description and r; select r, edit Equation to3.7,3.8 or3.9, and Run. Save Run then Compare can overlay trajectories; record the parameter values separately because those chart copies are not persistent parameter presets. Existing MCP compare_scenarios supports the three explicit overrides documented in the historical proposal.

Aliases preserve Population trajectories, not identical diagnostic column names. The r=3.7 original Growth_Rate means constant r; the r=3.8 original means r*(1-Population). The canonical names Instantaneous Log Slope and Coarse Parameter Range Code replace overstated diagnostic names. These are not an averaged Lyapunov exponent or proof of chaos. Exact original columns and arithmetic ordering are documented in operations/may-consolidation-proposal/OUTPUT-COMPATIBILITY.json; all original definitions and all three default reference series remain archived.

The historical proposal in MAY-MODEL-MIGRATION.md correctly described the absence of redirects at its review date. This additive implementation supplies only the two missing-ID GET fallbacks above; it does not change every API operation into an alias. Explicit updates/deletes and missing-ID GET XMILE export retain their ordinary behavior. To export a loaded draft, use its existing Download JSON or draft XMILE controls. Unsupported discrete-period XMILE export explains using JSON rather than erasing the period. The separate export-error fix72cef78 must be included in the same quality release.

If the canonical generation contract is missing or incompatible, the fallback fails clearly instead of inventing a preset. Other unknown IDs keep404. Aliases do not alter the storage layer, model list, database or catalog count. Release still requires independent review, staged checks and a published deployment notice.
