# Native dimensional analysis

`app.core.units.analyze_units(model, time_units=None)` performs advisory static checks using the existing equation parser and identifier rules. It does not execute an equation, select a lazy branch, modify the model or prove scientific validity. The JSON-safe result contains `status` (`consistent`, `inconsistent`, `incomplete`), `errors`, `unknown`, `warnings`, `inferred` and `scientific_validity: not_established`. Errors take precedence over incomplete metadata. Missing metadata always prevents a consistent result, including missing simulation time units.

The optional time override is an explicit declaration, never a guessed default. A future-compatible optional `time_settings.units` is read when available. Older models remain numerically usable without units. Analysis findings should remain advisory and must not become a new simulation rejection rule. Suggested inferred dimensions are evidence from an equation, do not fill missing metadata, and never turn an incomplete report into a pass.

Checks include addition, subtraction, comparisons, result units, dimensional multiplication/division, bounded rational powers, dimensionless logarithm/exponential/trigonometric arguments, conditional branch compatibility, delay duration and initializer units, and flow units equal to each connected stock divided by simulation time. Stock equations initialize stocks; they are not derivatives. Signed initial stocks are dimensionally valid. Numeric literals are contextual quantities, allowing initial values, `MAX(0, stock)` and explicit rate coefficients; their units cannot be independently verified without named, annotated parameters.

Units use a deliberately small symbolic grammar: identifiers, `1`, multiplication, division, parentheses and numeric powers. Common plural aliases and explicit dimensionless labels are recognized. Different time scales such as hour and second remain distinct: no scale conversion is performed. Arbitrary unit names remain separate symbolic bases, so scientific equivalence and unit ontology are not guessed. Unsupported strings produce unknown diagnostics, not errors or claimed success. Grammar length, AST size/depth, dimension count and rational exponents are bounded. Named lookup tables use optional `input_units` and `output_units`; both table-call and `LOOKUP(table, input)` forms check the input axis and return the output axis. Missing axis metadata and inline WITH_LOOKUP units remain unknown. Unsupported functions likewise produce unknown evidence. Both branches of a lazy conditional are checked statically; neither branch is executed.

The implementation is original Python code. The comparison reference is Simlin [units_check.rs at 3f87e9024a580b86b65e3d0c5c3353660fc5426e](https://github.com/bpowers/simlin/blob/3f87e9024a580b86b65e3d0c5c3353660fc5426e/src/simlin-engine/src/units_check.rs), reviewed for expression-level checks, contextual literals and explicit dependency units. No upstream code was copied. This analyzer intentionally uses stricter dimensionless transcendental-function arguments and supports bounded fractional dimensions; it is not a reproduction of every Simlin unit rule or an interoperability claim.

Verification: `python -m pytest -q tests/test_dimensional_analysis.py` covers valid and invalid stock flows, incompatible dollars and quality, dimensionless ratios, powers/log/trig, aliases and quoted identifiers, missing metadata, signed initial conditions, initial-condition expressions, delays and bounded parsing.

Additional limits cap whole-model analysis at 500 elements, 500 tables, two million element equation/unit characters and 100,000 visited expression nodes. Duplicate IDs or canonical aliases prevent a consistent report. Boolean literals are dimensionless, while numeric literals may take contextual units. Function signatures, random seeds, binomial arguments, delay orders, ROUND precision and power exponents are checked independently. Three-argument POW units remain explicitly unknown. Missing auxiliary equations and text reports remain incomplete. Units never establish numeric function-domain validity.
