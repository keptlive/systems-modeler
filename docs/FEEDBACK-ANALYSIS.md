# Quantitative local feedback response

`app.core.feedback_analysis.analyze_feedback(model, result, sample_count=8, relative_step=1e-4)` is opt-in, read-only analysis of a supplied numeric trajectory. It runs bounded perturbation evaluations, never a second complete simulation. The caller supplies the result and is responsible for matching its provenance to the model. The API adapter should run this only on explicit request and may use an existing successful simulation result.

The method is local stock-rate linearization. For continuous stocks x and algebraic net stock rates F(x,t), it estimates J[i,j] = dF_i/dx_j using central finite differences. Each perturbation holds time and other stocks fixed, then recomputes every auxiliary and flow through the existing canonical evaluator, including aliases, table behavior and lazy equations. Inflow/outflow signs determine F; stock equations remain initializers. Every sampled output includes its state, net rates, matrix, eigenvalues and spectral abscissa (largest real eigenvalue). Matrix rows and columns follow `stock_order`. A diagonal entry measures the net instantaneous response of a stock's own rate through all algebraic pathways; its sign is labeled reinforcing/balancing/neutral. These entries are dimensional derivatives, not normalized loop-attribution fractions.

For each column, the perturbation is `h = relative_step * max(1, abs(x_j))`. The matrix is recomputed with h/2 and compared with h. A one-sided slope is also compared to the central estimate, because a symmetric difference alone can conceal a cusp. Differences above an absolute-plus-relative heuristic tolerance mark the local indication unresolved. Domain errors (for example square root at zero under a negative perturbation) produce an unresolved sample rather than a substituted value. Small rates near the numerical tolerance are conservatively marginal/neutral. The default scaling uses the model's authored numeric coordinates; rescaling units or tolerances may affect finite-difference conditioning. No error bound or differentiability proof is implied.

Positive/negative spectral abscissa gives a locally amplifying/contracting frozen-time indication when perturbation checks agree. At a smooth autonomous equilibrium the usual linearization conditions apply; at arbitrary trajectory points, in time-dependent systems or near a zero eigenvalue this is only local evidence. Stable eigenvalues do not exclude transient amplification, and local contraction does not prove global stability or scientific validity. A logistic model, for example, has a positive local slope below half its carrying capacity and a negative one above it; these results are quantitative local response, not changing relative loop dominance.

Hard limits: 1–16 stocks, at most 128 elements, 1–16 sampled states, 200,000 charged equation attempts including dependency retries. Sampling includes evenly spaced retained trajectory indices; it can miss behavior between them. Hidden-state delay/smooth primitives and random equations are explicitly rejected, because a stock-only Jacobian omits their internal states or changes the noise realization. Discrete recurrences are rejected because their stability uses a transition-map Jacobian instead. Supplied stock series must be present, aligned and finite, with finite strictly increasing times. Invalid arguments raise ValueError; individual perturbation failures return partial evidence. This does not mutate any model, equation or result and does not change the simulation engine.

## Relationship to Simlin Loops That Matter

Primary reference reviewed: [Simlin ltm_augment.rs at 3f87e9024a580b86b65e3d0c5c3353660fc5426e](https://github.com/bpowers/simlin/blob/3f87e9024a580b86b65e3d0c5c3353660fc5426e/src/simlin-engine/src/ltm_augment.rs), particularly its ceteris-paribus link-score generation and flow-to-stock formulas. Simlin constructs historical partial changes by holding other inputs at previous values, compares partial target changes against actual target changes, and combines scored links into loop analyses. Its flow-to-stock construction uses the signed ratio of a flow change to net-flow change. Those historical attribution formulas are different from instantaneous derivatives.

This implementation is original Python code, with no upstream code copied. It supplies a useful bounded quantitative feedback diagnostic while reserving `dominance: not_computed` and `scientific_validity: not_established` in every report. It does not claim Simlin parity, LTM scores, individual loop attribution or causal identification from observations. Graph cycles alone would establish none of those quantities. Implementing full LTM later requires explicit historical instrumentation, hidden-state handling, cycle enumeration budgets and independent attribution tests.

Validation: `python -m pytest -q tests/test_feedback_analysis.py` covers independent analytic derivatives for linear growth and decay, logistic sign changes and a two-stock oscillator with eigenvalues ±2i; cusp detection, unsupported hidden-state/random cases, bounds, malformed trajectories and physical-domain perturbation failures are also tested.

Provenance hardening: reports include the normalized analyzed model hash and an explicit `unverified` provenance status when no source hash accompanies the result. A declared `integration_diagnostics.normalized_model_sha256` must match this lowered scalar model including effective settings, or analysis is rejected. When auxiliary/flow series accompany the stock trajectory, their sampled values are compared to recomputed baseline equations; disagreement makes that sample unresolved. These checks can detect mismatches but cannot authenticate caller-supplied evidence or identify a stale stock-only trajectory. Callers must associate results with the exact model themselves. Report-only text variables are excluded from numerical rates. Trajectories exceeding 100,001 retained states are rejected.

HTTP integration tests require an explicit result, forbid implicit simulation, exercise structured source lowering and read-only units/feedback behavior, and check argument errors.
